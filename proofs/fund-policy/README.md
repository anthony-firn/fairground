# Fund policy assurance boundary

The transaction conversion path calls `src/fundPolicy.ts`, which executes a
379-byte, dependency-free Rust/Wasm policy, before signing. It checks integer
ranges, retains the account reserve and fee budget, and denies automatic
spending for inactive accounts or another signing authority. Rust uses saturating
and checked subtraction so unsigned addition cannot wrap an approval into existence.
The three exported ABI symbol declarations require a narrowly scoped Rust lint
allowance; there are no unsafe blocks, keys, network calls, allocator or host imports.

`Policy.bend` is a mathematical model of the saturating-subtraction policy.
`LAWS.bend` states conservation for every natural-number balance/reserve, exact
surplus, inactive/external-authority denial, and preservation of reserve plus fees.
`PROOF.bend` proves those five laws by structural reasoning, without unsafe/foreign
proof code or admitted claims. Run:

```
cargo test --manifest-path crates/fund-policy/Cargo.toml --locked
python3 tools/build-fund-policy.py
python3 tools/check-fund-proofs.py
node --test test/fund-policy.test.ts
```

Bend is pinned to 2.0.40; its archive checksum is pinned in the installer.
`--verdict` also checks with BendTT's Lean-based kernel using Lean 4.34.0.
Telemetry is disabled for checks. Nothing is uploaded to Bend's hub.

Local kernel cross-check on November 18, 2026: the unmodified BendTT source
SHA-256 `776bfba6f08e9cbebb26fb3d43fa892b80d1d74b0a57698db4bc5d6b5db5b567`
was compiled and its included Lean proofs checked with the already installed
Lean 4.34.0-rc2, then supplied through `BENDTT` to the verdict checker. All five
laws passed. CI uses Bend's requested stable Lean 4.34.0; that is a distinct
toolchain check. The failed local stable-toolchain installation and its archive
were removed rather than consuming the machine's remaining disk space.

**These are model proofs, not a proof of the Rust implementation or the complete
wallet.** The Rust/Wasm implementation is tested against independent unbounded
BigInt arithmetic, including uint64 limits and overflow cases. There is no
machine-checked refinement proof between Bend and Rust, nor a verified compiler
or JS/Wasm ABI here. The model uses unbounded naturals; Rust bounds values to u64
and saturates overflow in the reserve. Reproducible generated bytes and CI checks
help detect drift; tests do not bridge that gap mathematically.

Transaction parsing, cryptographic libraries, identity trust, router correctness,
browser/OS integrity, recovery, chain consensus and issuer controls are outside
these five proofs. Classical Ed25519 wallet signatures are unchanged. Do not call
the whole app “provably secure” or “quantum secure” based on this work.
